# 工程文档：基于STM32的裸机双轮平衡车

## 1. 工程概述

本工程实现了一个双轮自平衡小车的完整控制软件，运行在STM32F103（Cortex‑M3）微控制器上。软件完全基于**裸机**开发，不使用任何实时操作系统，通过主循环周期轮询与中断相配合的方式实现多任务并发。小车具备以下功能：

- 自动保持直立平衡，抵抗外部扰动；
- 接收串口遥控指令，实现前进、后退、转向；
- 实时监测电池电压，通过LED指示剩余电量；
- 通过按键一键启动/停止电机，并复位控制系统。

工程代码采用**模块化**设计，每个外设或功能独立为一个`.c/.h`文件，通过`config.h`中的宏开关选择编译。所有模块均遵循“初始化（`_init`）— 周期性处理（`_proc`）— 数据接口（`_get/_set`）”的统一模式。

本文档面向**刚入门嵌入式开发**的读者，将详细解释每个模块的内部原理、数据流、关键算法，以及开发过程中遇到的具体问题与解决方案。

## 3. 文件结构与模块详解

### 3.1 根目录文件

#### `config.h`
该文件仅包含预处理器宏，用于配置工程功能。每个宏对应一个模块的开关或选择。

```c
// #define TEST                     // 测试模式，不进入主循环
// #define USE_MPU6050
#define USE_MPU6500                 // 选择使用MPU6500传感器

// #define APP_USART2_ENABLE        // 调试串口（默认关闭）
#define APP_BATTERY_ENABLE
#define APP_BUTTON_ENABLE
#define APP_PWM_ENABLE
#define APP_ENCODER_ENABLE
#define APP_MPU_ENABLE
#define APP_MOTOR_ENABLE
#define APP_CONTROL_ENABLE
#define APP_RC_ENABLE
```

**作用**：在`main.c`中，这些宏决定哪些`_init()`被调用；在`app_mpu.c`中，决定温度换算系数。用户可通过注释/取消注释来裁剪功能，节省代码空间。

#### `main.c`
程序入口，流程如下：

1. `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_0);`  
   设置中断优先级分组为“0位抢占优先级，4位子优先级”。这意味着所有中断只有子优先级，不支持抢占嵌套（但硬件的优先级编号仍然决定了谁可以打断谁，此处实际仍支持优先级高低，只是没有分组间的抢占概念）。通常这样设置后，编码器中断（子优先级0）可以打断SysTick（子优先级1）等，仍然是嵌套的。

2. 如果未定义`TEST`宏，则根据`config.h`中的宏顺序调用各模块的`_init()`函数。**顺序很重要**：例如`app_pwm_init`必须在`app_motor_init`之前，因为电机PID依赖于PWM已配置。

3. 进入`while(1)`无限循环，依次调用所有模块的`_proc()`函数。注意这些`_proc()`内部使用`PERIODIC`宏实现周期执行，本身不会阻塞循环。

4. 如果定义了`TEST`宏，则执行对应的测试函数（如`test_encoder_Tmethod()`），该函数自己是一个无限循环，不再执行主循环。

#### `stm32f10x_it.c` 和 `stm32f10x_it.h`
标准库提供的中断服务函数模板。本工程实现了以下中断：

| 中断处理函数         | 触发源                      | 主要任务                                             |
| -------------------- | --------------------------- | ---------------------------------------------------- |
| `SysTick_Handler`    | SysTick 每1ms               | 累加全局节拍计数器（毫秒），并辅助生成微秒时间戳     |
| `ADC1_2_IRQHandler`  | ADC1注入转换结束（JEOC）    | 读取电池电压，存入全局变量`vbat`                     |
| `EXTI15_10_IRQHandler`| 左编码器A相（PB14）边沿    | 判断方向，累加脉冲计数，记录中断时刻（用于T法测速） |
| `EXTI3_IRQHandler`   | 右编码器A相（PB3）边沿     | 同上                                                |
| `USART3_IRQHandler`  | USART3接收数据寄存器非空   | 接收遥控命令，缓存直到换行符                        |

#### `system_stm32f10x.c/h`
标准库的系统时钟配置文件。`SystemInit()`在启动文件中被调用，将系统时钟设置为72MHz（通过外部8MHz晶振，PLL倍频9倍）。用户无需关心内部细节。

### 3.2 应用模块（apps目录）

每个模块都对应一个外设或一项功能，下面逐一剖析。

#### 3.2.1 电池监测模块 (`app_battery.c/h`)

**目标**：测量电池电压（2S锂电池，满电8.4V，亏电6.0V），通过3个LED显示电量等级，并在电压过低时闪烁报警。

**硬件原理**：电池电压通过两个等值电阻（如10k+10k）分压，得到1/2的电压输入到PB0（ADC1通道8）。STM32的ADC参考电压为3.3V，因此最大可测电压为6.6V，分压后实际电池电压最大为13.2V，满足8.4V量程。分压比修正后，代码中通过`vbat = jdr1 * 2.0513e-3`将ADC值转换为真实电压。

**初始化 `app_battery_init()`**：
1. 配置TIM2：产生100Hz的更新事件（周期10ms），并设置为ADC注入转换的触发源。  
   `TIM_Period = 720-1`，`TIM_Prescaler = 1000-1`，72MHz / 1000 / 720 = 100Hz。
2. 配置ADC1注入序列：通道8，单次转换，采样时间7.5周期。  
   使能注入转换结束中断（JEOC），并使能外部触发（来自TIM2 TRGO）。
3. 配置三个LED引脚（PA4,5,6）为推挽输出，初始熄灭。

**中断处理**：当TIM2触发ADC注入转换完成后，`ADC1_2_IRQHandler`被调用。读取注入数据寄存器JDR1，计算实际电压，存入`volatile float vbat`（volatile保证在主循环中读取时不会被编译器优化掉）。

**周期函数 `app_battery_proc()`**：
- 根据`vbat`与预设阈值（7.9, 7.4, 7.0, 6.5）比较，点亮不同数量的LED。
- 若电压低于6.5V，则LED以200ms周期闪烁（通过检查`GetTick()`差值实现非阻塞闪烁）。

**开发中遇到的问题**：早期版本ADC中断中没有清除JEOC标志位，导致中断处理函数被连续重复进入，程序卡死。后来加入`ADC_ClearFlag(ADC1, ADC_FLAG_JEOC)`解决。

#### 3.2.2 按键模块 (`app_button.c/h`)

**目标**：检测用户单击，切换电机使能状态，并复位控制系统。

**硬件**：PA11配置为上拉输入，按键按下时接地（低电平）。

**初始化**：调用`My_Button_Init()`注册一个按钮对象，设置回调函数`button_pressed_handler`。

**回调函数**：每次单击时，反转`pwm_state`，调用`app_pwm_cmd(pwm_state)`使能或禁用电机驱动；同时调用`app_conrtol_reset()`和`app_motor_reset()`复位PID积分项和目标值。

**周期函数 `app_button_proc()`**：调用`My_Button_Proc()`处理按键状态机（消抖、边沿检测），当检测到有效单击时触发回调。

**注意**：此按键是电平触发，因此状态机内部会处理“按下-释放”时序，确保每次单击只响应一次。

#### 3.2.3 PWM电机驱动模块 (`app_pwm.c/h`)

**目标**：控制TB6612驱动芯片，实现两个电机的正反转及速度调节。

**初始化 `app_pwm_init()`**：
- 设置PA1为推挽输出，初始低电平（STBY=0，电机驱动休眠）。
- 设置方向控制引脚（PA9,10,PB5,7）为推挽输出，初始低电平。
- 配置TIM1和TIM4的通道1为PWM模式1：  
  预分频器PSC=0（即1分频），自动重载ARR=999，因此PWM频率 = 72MHz / (0+1) / (999+1) = 72kHz。  
  占空比通过CCR寄存器控制：CCR值范围0～1000，对应0%～100%。
- 使能TIM1的MOE位（主输出使能），因为TIM1是高级定时器，必须设置该位才有PWM输出。

**API函数**：
- `app_pwm_cmd(state)`：state=1时置高STBY，state=0时拉低STBY。
- `app_pwm_set_L(duty)`：输入-100.0～100.0。  
  先判断正负，设置方向引脚（正转：IN1高IN2低；反转：IN1低IN2高）。  
  然后取绝对值，计算CCR = (|duty|/100) * 1000。由于ARR=999，CCR值最大为999，这里用1000是为了计算方便，但实际写入时要限幅到999。
- `app_pwm_set_R(duty)`：类似，但方向引脚不同。

**开发中遇到的问题**：TIM1是高级定时器，需要额外调用`TIM_CtrlPWMOutputs(TIM1, ENABLE)`才能输出PWM，否则引脚无波形。早期忽略此步骤，电机不转。

#### 3.2.4 编码器测速模块 (`app_encoder.c/h`)

**目标**：测量两个车轮的角位置（累计角度）和角速度（rad/s），采用**T法测速**。

**原理**：T法通过测量相邻两个编码器脉冲之间的时间间隔来计算速度，特别适合低速场合。每个编码器每圈产生N个脉冲（本工程中，减速电机编码器线数×减速比×4倍频后，每个脉冲对应角度`R2R = 2π / ((30613/1500)*22)` ≈ 0.014 rad）。在A相每个边沿中断中记录时间戳，计算速度。

**初始化 `app_encoder_init()`**：
- 左编码器：PB14（A相）配置为EXTI Line14，上升沿和下降沿均触发；PB15（B相）配置为普通输入上拉。  
  注意EXTI需要`RCC_APB2Periph_AFIO`时钟。
- 右编码器：PB3（A相）配置为EXTI Line3，需先禁用JTAG。PB4为B相。  
  禁用JTAG：`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE);`。

**中断处理逻辑**（以左编码器为例）：
```c
// 读取A相和B相电平
uint8_t phase_a = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_14);
uint8_t phase_b = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_15);
// 更新时间戳
encoder_t0_L = encoder_t1_L;
encoder_t1_L = GetUs();
// 判断方向（AB相正交编码规律）
if (phase_a == phase_b) {
    encoder_acc_L++;   // 正转
    encoder_direction_L = 1;
} else {
    encoder_acc_L--;   // 反转
    encoder_direction_L = -1;
}
```
**注意**：方向判断取决于A相与B相的相位差。对于增量编码器，通常A相超前B相90°表示正转。这里简单判断`phase_a == phase_b`是可行的，因为每次中断发生在A相边沿，此时B相电平决定了方向。但实际接线方向可能相反，需要现场测试调整符号。

**T法测速实现**：
```c
float app_encoder_getw_L(void) {
    __disable_irq();   // 关中断保护，复制时间戳和方向
    int8_t dir = encoder_direction_L;
    uint64_t t0 = encoder_t0_L;
    uint64_t t1 = encoder_t1_L;
    __enable_irq();

    uint64_t now = GetUs();
    uint64_t dt = t1 - t0;
    if (now - t1 > dt) dt = now - t1;   // 取较大值，防止时间差过小
    if (dt == 0) return 0;

    float raw_w = (R2R * dir) / (dt * 1e-6);
    // 低通滤波
    encoder_filtered_w_L = 0.3f * raw_w + 0.7f * encoder_filtered_w_L;
    return encoder_filtered_w_L;
}
```
- 使用`__disable_irq()`保护临界区，避免在复制过程中被编码器中断修改数据。
- 时间差取`max(t1-t0, now-t1)`，原因：如果当前时刻`now`距离上一次中断`t1`已经很长（比如很久没有新脉冲），说明转速很低，此时用`now-t1`作为周期更合理。
- 滤波系数0.3，可调。滤波后速度平滑，但会引入滞后，需要权衡。

**获取角度**：`app_encoder_getpos_L()`返回`encoder_acc_L * R2R`，单位弧度。

**开发中遇到的问题**：
1. **T法测速噪声大**：早期未加低通滤波，速度值跳动剧烈，导致电机PID震荡。加入一阶低通滤波后明显改善。
2. **编码器中断优先级过低**：如果被其他中断长时间占用，会丢失脉冲，导致速度测量不准。解决方法：将编码器中断优先级设为最高（子优先级0）。
3. **方向判断错误**：实际接线可能A/B相反，导致符号反了。通过测试反转后，软件中交换条件或调整`R2R`符号解决。
4. **JTAG禁用问题**：右编码器使用PB3/PB4，默认被JTAG占用，必须禁用JTAG，否则引脚无法作为普通GPIO输入。但禁用后不影响SWD调试。

#### 3.2.5 MPU姿态传感器模块 (`app_mpu.c/h`)

**目标**：读取MPU6050或MPU6500的加速度和角速度数据，通过互补滤波计算出俯仰角（pitch）、横滚角（roll）和偏航角（yaw）。对于平衡车，主要使用俯仰角。

**初始化 `app_mpu_init()`**：
- I2C1硬件初始化：重映射到PB8/PB9，400kHz模式。
- 通过I2C写MPU寄存器：  
  电源管理寄存器（0x6B）先写0x80复位，延时100ms后写0x00唤醒。  
  陀螺仪配置寄存器（0x1B）写0x18（选择±2000°/s量程）。  
  加速度计配置寄存器（0x1C）写0x00（选择±2g量程）。
- 本工程支持MPU6050和MPU6500，通过`config.h`中的宏选择温度换算系数（但温度未用于控制，仅调试）。

**数据读取 `app_mpu_update()`**：
- 依次读取加速度计、陀螺仪、温度的原始寄存器（每个轴高8位和低8位），拼接成16位有符号整数。
- 转换成物理值：  
  加速度：原始值 × 2g / 32768 = 原始值 × 6.1035e-5（代码中`A_I2F`）。  
  角速度：原始值 × 2000°/s / 32768 = 原始值 × 6.1035e-2（`G_I2F`）。  
  温度：MPU6050为 `raw/340 + 36.53`，MPU6500为 `raw/333.87 + 21.0`。

**姿态解算 `app_mpu_proc()`**（周期5ms）：
1. 调用`app_mpu_update()`获取最新原始数据。
2. 角速度积分：`pitch_g = pitch + gx * DELTA_T`，`DELTA_T = 0.005`秒。
3. 加速度计算角度：`pitch_a = atan2(ay, az) * 57.29578`（弧度转度）。注意这里用`atan2(ay, az)`，因为平衡车横放时y轴为车身前后方向，z轴为垂直地面方向。实际可能根据MPU安装方向调整。
4. 互补滤波：`pitch = COMPOUND_FILTER * pitch_a + (1-COMPOUND_FILTER) * pitch_g`，系数0.95238。
5. 同理计算roll和yaw，但yaw无地磁参考会漂移，未用于控制。

**为什么要互补滤波**：加速度计测量值包含重力分量，长期稳定但动态噪声大；陀螺仪积分短期准但长期漂移。互补滤波结合两者优点。

**开发中遇到的问题**：
- **I2C通信失败**：早期使用软件模拟I2C，速度慢且不稳定。后改用硬件I2C并正确配置重映射和上拉电阻，问题解决。
- **欧拉角方向反了**：加速度计算出的pitch符号与车身实际倾斜方向相反，通过交换`atan2`参数或取负号调整。
- **互补滤波参数选择**：系数过于接近1（过分信任加速度计）会导致姿态抖动；过于接近0（信任陀螺仪）则漂移明显。经验值0.95~0.99。

#### 3.2.6 电机速度闭环模块 (`app_motor.c/h`)

**目标**：对每个轮子独立进行PID速度控制，使实际转速跟随设定值。

**初始化**：设置左右电机PID参数（Kp=0.55, Ki=7.0, Kd=0），输出限幅±8.4V（对应占空比±100%），积分限幅与输出限幅相同。

**周期函数 `app_motor_proc()`**（每1ms执行）：
1. 调用`app_encoder_getw_L()`和`app_encoder_getw_R()`获取当前角速度（已经过低通滤波）。
2. 调用`PID_Compute1(&motor_pid_L, w_L, now)`获得PID输出值（单位：电压，伏特）。
3. 计算占空比：`duty = Um / vbat * 100`，并限幅到-100～100。
4. 调用`app_pwm_set_L(duty)`和`app_pwm_set_R(duty)`。

**API**：`app_motor_setw_L(float w)`和`app_motor_setw_R(float w)`用于修改PID设定值（目标转速）。

**注意**：PID的Ki=7.0较大，这意味着积分作用强，可以快速消除静差，但容易引起超调。输出限幅保证了电机不会过驱动。

#### 3.2.7 倒立摆串级控制模块 (`app_control.c/h`)

这是平衡车的**核心算法**，实现了串级PID与运动学/动力学相结合的控制策略。

**为什么要串级**：倒立摆是一个非最小相位系统，单环PID很难同时实现稳定性和响应速度。串级控制将系统分解为：

- **内环**（角速度环）：响应最快，直接抑制车身倾斜角速度，相当于增加系统阻尼。
- **中环**（角度环）：根据当前角度和期望角度（由速度环给出）计算期望角速度。
- **外环**（速度环）：根据车辆实际平动速度与期望速度（遥控命令）的误差，计算期望倾斜角。

**初始化**：设置四个PID控制器的参数。
- 速度环：Kp=10.0, Ki=1.0, Kd=0，输出限幅±0.3*9.8（即最大期望倾斜加速度±2.94 m/s²）。
- 角度环：Kp=4.0, Ki=0, Kd=0，输出限幅±12.57 rad/s（±4π rad/s，即最大期望角速度）。
- 角速度环：Kp=10.0, Ki=10.0, Kd=0，输出限幅±125.7 rad/s²（±40π rad/s²）。
- 转向环：Kp=1.0, Ki=0, Kd=0，输出限幅±15 rad/s（左右轮速度差）。

**周期函数 `app_control_proc()`**（每5ms执行）：
1. **获取当前数据**：
   - 平均轮速 `encoder_w = (w_L + w_R)/2`。
   - 车身俯仰角 `theta = pitch * D2R`（度转弧度）。
   - 车身俯仰角速度 `theta_dot = gx * D2R`（度/秒转弧度/秒）。
   - 偏航角速度 `turn = gz * D2R`。
2. **运动学分离**：编码器测得的轮速包含两部分：车身平动引起的轮速和平动速度`x_dot`与轮半径`R`的关系，以及车身倾斜时车轮自然转动的附加分量。  
   附加分量 = `-theta_dot * (L+R)/R`（负号表示前倾时车轮自动向后转）。  
   因此平动速度 `x_dot = (encoder_w - (-theta_dot*(L+R)/R)) * R`。
3. **速度环**：输入为`x_dot`，期望速度由遥控命令给出（初始为0）。速度环输出为期望倾斜角`theta_ref`（单位弧度）。  
   `theta_ref = PID_Compute1(&contorl_velocity, x_dot, now)`。注意速度环输出是角度值，但需要限幅到实际可行范围（例如±0.3 rad）。代码中使用了`qatan`函数将速度环输出转换？查看代码：`theta_ref = qatan(PID_Compute1(&contorl_velocity, x_dot, now) / STD_G)`，即先将PID输出（加速度）除以重力加速度，再反正切得到角度。这是一种转换方法，实际PID输出应为期望平动加速度。
4. **角度环**：输入实际`theta`，期望`theta_ref`，输出期望角速度`theta_dot_ref`。  
   `theta_dot_ref = PID_Compute1(&contorl_theta, theta, now)`。
5. **角速度环**：输入实际角速度`theta_dot`，期望`theta_dot_ref`，输出期望角加速度`theta_dotdot_ref`。  
   `theta_dotdot_ref = PID_Compute1(&contorl_theta_dot, theta_dot, now)`。
6. **逆动力学**：从期望角加速度求解期望平动加速度。倒立摆动力学方程近似：  
   `x_ddot = (g*sin(theta) - theta_ddot * L) / cos(theta)`。  
   因此 `x_ddot_ref = (g*sin(theta) - theta_dotdot_ref * L) / cos(theta)`。  
   注意当`cos(theta)`趋近0时（车身水平）会发散，但由于平衡车只在±0.3 rad范围内工作，安全。
7. **积分得到期望轮速**：`omega_ref += x_ddot_ref * dt / R`，其中`dt`是两次`app_control_proc`调用的时间差（5ms）。
8. **转向环**：根据偏航角速度`turn`与期望转向速度（遥控命令）的误差，计算左右轮差速`omega_diff = PID_Compute1(&contorl_turn, turn, now)`。
9. **设定电机目标**：左轮目标速度 = `omega_ref + omega_diff`，右轮目标速度 = `omega_ref - omega_diff`，调用`app_motor_setw_L/R`。

**复位函数 `app_conrtol_reset()`**：清零`omega_ref`，并复位所有PID控制器（清零积分累加和上一次误差）。在按键回调中被调用。

**开发中遇到的问题**（根据commit log）：
- **omega_ref累积过快**：早期版本未对`omega_ref`做限幅，导致积分项发散，车轮疯狂加速。解决：在速度环输出和`omega_ref`积分处增加限幅，且由于车身实际存在摩擦，最终会平衡。
- **控制顺序导致数据不同步**：早期在`app_control_proc`中先获取角度再获取编码器速度，两者时间差可能引起计算错误。解决：在函数开头一次性获取所有时间敏感数据，并用局部变量保存。
- **角度环方向反了**：期望角度与实际角度符号关系错误，导致正反馈，小车立刻倒下。解决：通过实验确定正确方向，调整PID设定值符号。
- **测试时带负载与空载差异**：空载时车轮转动阻力小，`omega_ref`容易累加过快，需降低速度环增益或增加空载检测。

#### 3.2.8 遥控模块 (`app_rc.c/h`)

**目标**：通过串口接收遥控命令，实时调整小车的期望速度。

**硬件**：USART3，PB10(Tx), PB11(Rx)，波特率9600，8N1。

**初始化**：配置USART3，使能接收中断（RXNE）。NVIC优先级设为子优先级0（较高）。

**中断处理**：每个字符到达时，存入`int_buf`，当收到`'\n'`（换行）时，将缓冲区内容复制到`trans_buf`，并置标志`line_received_flag = 1`。注意缓冲区大小限制（64字节），防止溢出。

**周期函数 `app_rc_proc()`**：检查标志，若有新命令，则解析。命令格式：`move <turn_percent> <speed_percent>`，例如`move 30 -50`。  
- `turn_percent`范围-100～100，映射到转向角速度±15 rad/s。  
- `speed_percent`范围-100～100，映射到平动速度±0.7 m/s。  
调用`app_conrtol_set_move_speed(speed)`和`app_conrtol_set_turn_speed(turn)`。

**注意**：命令解析使用`strncasecmp`（忽略大小写）和`sscanf`。如果解析失败，忽略该命令。

### 3.3 底层库（mylib目录）

#### `delay.c/h` 与 `PERIODIC` 机制

**核心变量**：
- `volatile __IO uint32_t ulTicks`：由`SysTick_Handler`每1ms增加1，表示系统上电后的毫秒数。
- `static uint64_t usTicks`：微秒计数器，通过`GetUs()`动态计算。

**`GetUs()` 实现原理**：
```c
uint64_t GetUs(void) {
    uint32_t ticks = ulTicks;
    uint32_t val = SysTick->VAL;           // 当前递减计数器的值
    uint32_t reload = SysTick->LOAD + 1;   // 重装载值（1000）
    uint64_t us = ticks * 1000 + (reload - val) * (1000 / reload);
    return us;
}
```
- SysTick每1ms重装载一次，递减计数。假设重装载值为1000，则每个计数对应1微秒（72MHz/1000=72kHz，每个计数实际时间=1/72kHz≈13.9μs？此处需要根据系统时钟精确计算。本工程中SysTick配置为72MHz/1000=72kHz，每个计数周期为13.89μs，因此`(reload - val) * (1000 / reload)`得到微秒数不精确。事实上更常用的方法是直接读取`SysTick->VAL`并结合`ulTicks`，但误差可接受。为简化，本工程采用此近似。）

**`PERIODIC(ms)` 宏**：
```c
#define PERIODIC(ms) \
    static uint32_t _last_time = 0; \
    uint32_t _now = GetTick(); \
    if (_now - _last_time < (ms)) return; \
    _last_time = _now;
```
- 在每个`_proc`函数开头放置该宏，实现非阻塞的周期调用。
- 通过静态变量`_last_time`记录上次执行的时间，如果当前时间与上次时间差小于指定毫秒数，则直接`return`。
- 这种模式称为“时间片轮询”或“协作式调度”，不需要RTOS。

**`Delay(ms)` 阻塞延时**：通过循环执行`while(ms--){ for(i=0; i<1000; i++); }`粗略延时，仅用于初始化等待，不用于实时控制。

#### `pid.c/h` 详细逻辑

**数据结构**：
```c
typedef struct {
    float Kp, Ki, Kd;
    float Setpoint;
    float Integral;
    float PrevError;
    float OutputLowerLimit, OutputUpperLimit;
    float DefaultOutput;
    uint64_t LastTime;
} PID_TypeDef;
```

**初始化函数**：设置系数、设定值、输出限幅，清零积分项和上一次误差。

**核心计算函数** `PID_Compute1(PID_TypeDef *pid, float input, uint64_t now)`：
1. 计算时间差`dt = (now - pid->LastTime) / 1e6`（秒）。
2. 计算误差`error = pid->Setpoint - input`。
3. 比例项`P = pid->Kp * error`。
4. 积分项`I = pid->Ki * error * dt`，然后累加到`pid->Integral`，并进行积分限幅（限制在输出限幅范围内）。
5. 微分项`D = pid->Kd * (error - pid->PrevError) / dt`。
6. 计算总输出`Output = P + pid->Integral + D`。
7. 对输出进行限幅`if(Output > pid->OutputUpperLimit) Output = pid->OutputUpperLimit;`等。
8. 更新`pid->PrevError = error; pid->LastTime = now;`。
9. 返回输出值。

**注意**：本工程中，当`dt`非常小（例如第一次调用）时，微分项会很大，因此代码中应有保护，或者在实际调用时确保第一次时间差不参与微分计算。

**为什么需要积分限幅**：防止积分项无限累积导致输出饱和，当误差反向时退出饱和变慢。

#### `i2c.c/h`、`usart.c/h`、`button.c/h`、`qmath.c/h`
- `i2c`：提供了基于硬件I2C的发送和接收函数（`My_I2C_SendBytes`, `My_I2C_ReceiveBytes`），内部处理了起始条件、地址、等待标志等。
- `usart`：`My_USART_Printf`支持可变参数，内部调用`vsprintf`格式化字符串，再逐字节发送。
- `button`：按键状态机，支持单击和长按，使用定时器查询（而不是中断）。
- `qmath`：使用查表法实现快速三角函数，精度0.1°，适合控制环路。

## 4. 上电工作流程（完整时序）

1. 硬件复位 → 启动文件调用`SystemInit()`配置时钟（72MHz）。
2. 跳转到`main()`。
3. 设置中断优先级分组（`NVIC_PriorityGroup_0`）。
4. 根据`config.h`依次调用各模块`_init`：
   - `app_usart2_init()`：调试串口（若启用）。
   - `app_battery_init()`：ADC、TIM2、LED。
   - `app_button_init()`：按键GPIO、回调注册。
   - `app_pwm_init()`：PWM定时器、方向引脚。
   - `app_encoder_init()`：编码器GPIO、EXTI中断。
   - `app_mpu_init()`：I2C、MPU寄存器配置。
   - `app_motor_init()`：电机PID参数。
   - `app_control_init()`：串级PID参数。
   - `app_rc_init()`：USART3中断。
5. 进入`while(1)`主循环：
   - 依次调用`app_button_proc()`, `app_battery_proc()`, `app_mpu_proc()`, `app_motor_proc()`, `app_rc_proc()`, `app_control_proc()`。
   - 每个`_proc`内部通过`PERIODIC`宏实现非阻塞周期执行。
6. 中断随时发生：
   - `SysTick_Handler`每1ms更新`ulTicks`。
   - 编码器中断更新脉冲计数和时间戳。
   - ADC中断更新`vbat`。
   - USART3中断接收遥控命令。

**控制环路的实际执行时间线**：
- 电机PID每1ms执行一次，读取最新编码器速度，更新PWM。
- 姿态解算和控制算法每5ms执行一次，读取MPU和编码器数据，更新电机目标速度。
- 由于编码器中断优先级最高，即使主循环中`app_motor_proc`调用速度计算时，也能获取到最新的时间戳。

## 5. 开发调试中的问题与解决方案（基于commit log）

### 5.1 ADC中断标志未清除导致重复进入
- **现象**：电池电压读取正常，但程序很快卡死或行为异常。
- **原因**：`ADC1_2_IRQHandler`中没有调用`ADC_ClearFlag(ADC1, ADC_FLAG_JEOC)`，导致中断标志位一直置位，退出后再次立即进入，形成无限中断嵌套。
- **解决**：在读取JDR1之后，添加`ADC_ClearFlag(ADC1, ADC_FLAG_JEOC);`。

### 5.2 编码器T法测速噪声大
- **现象**：打印速度波形毛刺严重，电机PID输出抖动。
- **原因**：T法测速的时间差计算中，直接用`t1 - t0`作为周期，当转速很低时，两个脉冲间隔很长，但若在`t1`之后很久才调用`getw`，`now - t1`远大于`t1 - t0`，用前者更合理。原代码未处理这种情况。
- **解决**：在`app_encoder_getw`中计算`dt = max(t1-t0, now-t1)`，且增加低通滤波。

### 5.3 编码器方向判断错误
- **现象**：电机正转时编码器角度减小，速度符号为负。
- **原因**：编码器AB相接线顺序与软件判断逻辑不匹配。
- **解决**：通过实验确认方向，修改中断中的符号条件（交换`if`分支）。

### 5.4 JTAG禁用问题导致右编码器不工作
- **现象**：左编码器数据正常，右编码器始终为0。
- **原因**：PB3/PB4默认被JTAG占用，作为普通IO使用时需要关闭JTAG。
- **解决**：在`app_encoder_init`中添加`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE);`。

### 5.5 TIM1高级定时器PWM无输出
- **现象**：调用`app_pwm_set_L`后，电机不转，示波器测量PA8无波形。
- **原因**：TIM1是高级定时器，需要使能MOE（主输出使能）位。
- **解决**：添加`TIM_CtrlPWMOutputs(TIM1, ENABLE);`。

### 5.6 MPU I2C通信失败
- **现象**：读取MPU ID始终为0。
- **原因**：早期使用软件模拟I2C，时序不准；后改用硬件I2C，但未正确开启重映射和上拉电阻。
- **解决**：使用硬件I2C1，重映射到PB8/PB9，并在外部加4.7k上拉电阻。

### 5.7 角度环方向反导致正反馈
- **现象**：小车一上电就向一边加速倒下。
- **原因**：PID输出符号与电机响应方向相反，形成正反馈。
- **解决**：通过测试，将角度环PID输出取反，或交换编码器方向。

### 5.8 omega_ref累积过快导致车轮飞转
- **现象**：平衡车在空载（无地面摩擦）时，车轮加速越来越快，无法控制。
- **原因**：速度环输出期望倾斜角，角度环和角速度环产生角加速度，逆动力学积分得到`omega_ref`。由于空载时没有地面反作用力，车身倾斜角度小，但积分项仍不断累加，导致速度发散。
- **解决**：对`omega_ref`进行限幅，限制最大轮速（例如±30 rad/s），同时适当降低速度环增益。

### 5.9 主循环中各模块执行顺序导致数据不同步
- **现象**：有时姿态控制出现异常抖动。
- **原因**：`app_control_proc`中先读取MPU角度，后读取编码器速度，两者时间差在5ms以上，导致计算所用数据不匹配。
- **解决**：在`app_control_proc`开头一次性读取所有需要的数据（通过调用`app_encoder_getw_L/R`内部会关中断复制，但MPU数据是实时读的）。由于MPU读取较慢，实际仍存在微小时间差，但影响减小。

### 5.10 互补滤波参数选择不当
- **现象**：俯仰角跟随响应慢或漂移大。
- **原因**：滤波系数过于偏向加速度计或陀螺仪。
- **解决**：调整`COMPOUND_FILTER`，典型值0.95～0.99。本工程使用0.95238，相当于加速度计权重4.76%，陀螺仪权重95.24%，响应较快且无漂移。

### 5.11 电机PID积分饱和
- **现象**：电机长时间未达到目标速度后，PID输出一直为最大值，导致超调。
- **原因**：积分项累积过大。
- **解决**：在PID计算中加入积分限幅，限制积分项不超过输出限幅范围。

## 6. 如何复刻与调参（简要指引）

### 6.1 硬件连接
按照第2.2节引脚表连接各模块。特别注意：
- 电机驱动TB6612的GND与STM32共地。
- 电池分压电阻（10k+10k）接入PB0，确保分压后电压不超过3.3V。
- MPU的I2C上拉电阻必须接。
- 编码器A相必须连接到支持EXTI的引脚。

### 6.2 软件修改
- 根据实际电机编码器线数和减速比修改`app_encoder.c`中的`R2R`常量。
- 根据MPU安装方向，可能需要调整`app_mpu.c`中`atan2`的参数顺序或取反。
- 根据机械尺寸修改`STD_L`（质心高度）和`STD_R`（轮半径）。

### 6.3 调参步骤
1. **开环测试**：取消`APP_CONTROL_ENABLE`，直接调用`app_pwm_set_L(30)`，观察电机转动方向，调整方向引脚逻辑。
2. **编码器测试**：手动转动车轮，串口打印角度和速度，确认符号正确且无跳变。
3. **MPU测试**：串口打印`pitch`，倾斜车身观察数值变化是否合理。
4. **速度闭环测试**：使能速度PID，设置目标转速（如10 rad/s），观察是否能稳定，调整`Kp`、`Ki`。
5. **角度环测试**：将小车固定转轴，手动倾斜，观察电机是否产生相反力矩，调整角度环`Kp`。
6. **完整串级调试**：由内向外逐环调试。先让角速度环稳定（用手转动车身，电机应产生反向力矩），再调试角度环，最后调试速度环。
7. **遥控调试**：发送`move 0 20`，小车应匀速前进。

### 6.4 常见问题快速排查表

| 现象                         | 可能原因                                        | 检查方法                                     |
| ---------------------------- | ----------------------------------------------- | -------------------------------------------- |
| 电机不转                     | STBY未使能；PWM未输出；电池没电                 | 测量PA1电压；示波器看PWM引脚；测量电池电压   |
| 编码器无脉冲                 | 中断未使能；引脚被占用；编码器线松              | 用逻辑分析仪抓PB14波形；检查JTAG禁用         |
| MPU无数据                   | I2C通信失败；地址错误；电源不稳                | 用示波器看SCL/SDA波形；读MPU ID（0x68）      |
| 小车向一边倒                 | 角度环方向反；电机线接反                       | 手动倾斜车身，观察电机响应方向是否相反       |
| 车轮剧烈抖动                 | 角速度环Kp过大；互补滤波系数太小               | 降低角速度环增益；增加加速度计权重           |
| 前进速度无法控制             | 速度环输出未正确转换；运动学分离错误           | 打印`x_dot`和`theta_ref`，检查关系是否合理   |
| 转向不受控                   | 转向环未启用或参数不当；遥控命令未解析         | 打印`omega_diff`和`turn`，检查PID输出        |
